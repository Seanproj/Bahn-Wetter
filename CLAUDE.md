# CLAUDE.md — Bahn-Wetter (DB 지연 예보)

`HANDOFF.md` is the single source of truth for scope, data, forecast logic and UI.
This file condenses the working rules. If they ever disagree, HANDOFF.md wins — update this file.

## What this is
A static website that shows Deutsche Bahn delay probabilities in playful formats: a daily fortune
(운세: 대길…대흉, 잠수) on the home page and share card, train character cards (랭킹) and a delay gacha
with a "100번 타면" grid (출퇴근 detail sheet). Detail views still use the weather icons (☀️…⛈️🌪️). Scope: Frankfurt (Main) Hbf hub + routes Frankfurt Hbf ↔ Darmstadt Hbf, Flughafen, Wiesbaden Hbf, Mainz Hbf,
Hanau Hbf (config/station_search.yaml → routes; Darmstadt was the original HANDOFF corridor).
Tone: fun and shareable, not a precision tool. UI language: Korean (de/en later).

## Hard rules
- **No guessed hardcoding.** Station names, EVA numbers, line lists and the parquet schema are
  read from the real data, then pinned in `config/`. Only *search patterns* live in
  `config/station_search.yaml`; `config/stations.yaml` is generated by `pipeline/explore.py`.
- Upstream schema has changed several times (2026-05 `train_name` split, 2026-08 `is_canceled`
  split, 2026-09 replacement/additional-stop columns, 2026-10 `has_plan_record`,
  `replaced_train_type`). Always check the actual parquet schema before writing queries.
- Delay definition: DB official — `delay_in_min >= 6` is delayed. Also track ≥15, ≥30, cancel rate.
- Every probability is stored with its sample size `n`. `n < 10` → UI shows "데이터 부족".
- Secrets (DB API keys) only in `.env`. Never commit `.env`.
- `data/` is gitignored. Work from the slim parquet cache (`data/slim/`), not the full monthly files.
- No DB logo/brand. Do not use "DB" alone as the name.
- Footer must show: `Daten: Deutsche Bahn (CC BY 4.0), via piebro/deutsche-bahn-data` + unofficial notice.
  CC BY 4.0 also requires a license link and a note that the data was processed (aggregated into
  probabilities); put both on the About page.
- Fixed disclaimer: "과거 패턴 기반 예보이며 파업·사고 등 돌발 상황은 반영되지 않습니다".
- Work in phases (HANDOFF §8). Stop at the end of each phase, report, wait for OK.
- Commit at meaningful units; English conventional-commit messages.

## Data facts (verified in Phase 0, see reports/phase0_summary.md)
- `train_line_ride_id` is a recurring timetable-pattern ID, **not** a single run. A single run is
  `ride_key = regexp_replace(id, '-[0-9]+$', '')`.
- `delay_in_min` is departure-based (arrival-based only at terminal stops). Compute arrival delay
  yourself from `arrival_change_time - arrival_planned_time`.
- Drop `has_plan_record = false` rows (no planned time, no delay, no train type).
- Frankfurt Hbf has two EVAs: `08000105` (surface) and `08098105` (S-Bahn tunnel).
- Corridor lines (2025-11..2026-09): S6, RB68, RE60, ICE (+ rare RB67). Not S3/S4.
- 2025-11/12 files have bare numeric line numbers ("6"); events.py prefixes the train type.
- `train_type = "Bus"` rows are planned rail-replacement buses; excluded.
- Trip (commuter) forecasts = arrival delay at the destination, keyed by origin departure hour.
- Routes (Phase 6): a route run = same ride_key at Frankfurt Hbf and the route endpoint. Direction keys are
  `ffm_<code>` / `<code>_ffm` (e.g. ffm_da, fra_ffm); each direction has its own line list (≥1 run/day).
- The airport is one station key with two EVAs: 08070004 (Regionalbahnhof) + 08070003 (Fernbahnhof).
- One S8 run can serve several routes (airport, Mainz, Wiesbaden): de-duplicate by ride_key / train for
  per-line stats (profiles.py) and the weekly ranking.

## Site conventions
- Today's day type is computed in the browser (Europe/Berlin time + Hessen holidays from meta.json),
  so the static JSON stays valid between data refreshes.
- Level logic lives only in `site/src/weather.ts`, driven by `config/weather.yaml`; each level carries both
  its weather icon and its fortune grade/copy (`fortune`, `fortune_text`).
- Playful views live in `site/src/fun.ts`: personas are derived from `corridor.json` → `characters`
  (pipeline/profiles.py) by fixed rules; the gacha picks a bucket from the tapped cell's own p6/p15/pc and a
  minute value from `dist` quantiles inside that bucket. No invented numbers.
- Route picker = route chips + from/to toggle; switching route keeps the travel direction. The share card's
  main slip uses the first route; its "오늘의 노선 운세" row shows every route's all-day average.
- The dex shows the 12 busiest lines across all routes.
- Themes per route via body[data-sky]: home/card = "fortune" (night + paper slip), ranking = "dex",
  commute/about keep the weather sky.
- The "가장 맑은 열차" pick ranks by P(bad trip) = p_cancel + (1 − p_cancel)·p_delay6 plus a small-sample
  penalty 0.67·sqrt(b(1−b)/n), and never picks 🌪️.
- The ranking is observed data for the last 7 days *of the data*, not the calendar week — always show its dates.
- `#/card?date=YYYY-MM-DD` renders the share card for any day; animated sky layers live in `#sky` and stop
  under prefers-reduced-motion.

## Layout
```
pipeline/            Python 3.12+, managed by uv
  download.py        incremental download of monthly_processed_data from Hugging Face
  explore.py         schema check, station search, corridor analysis → config/stations.yaml
  slim.py            filter monthly files to target EVAs → data/slim/*.parquet
  events.py          slim cache → clean stop/trip event tables (all filtering rules live here)
  model.py           hierarchical Beta-Binomial shrinkage + recency weights
  backtest.py        time-split backtest, Brier, calibration → config/model.yaml
  build_stats.py     final probability tables → data/stats/{stop,trip}_cells.parquet
  ranking.py         observed worst/best lines & trains in the last 7 days of data
  conditional.py     P(late arrival | origin departure delay) table + backtest → reports/conditional_backtest.md
  live.py            Timetables API snapshot → live.json (needs DB_CLIENT_ID/DB_API_KEY; --fixtures replays)
  profiles.py        per-line observed profiles (characters + delay quantiles) for the playful views
  export.py          static JSON → site/public/data/{meta,hub,corridor,ranking}.json
config/
  station_search.yaml  search patterns for target stations + route list (input)
  stations.yaml        resolved stations + EVA + routes (generated, then committed)
  weather.yaml         probability → weather icon thresholds and copy
  model.yaml           hyper-parameters chosen by backtest.py (generated)
  live.yaml            URL of the published live.json (raw.githubusercontent.com, branch live-data) + max age
site/                Vite + vanilla TS static site (src/: data, time, weather, views, fun, ranking, card, main)
cards/               make_card.py: Playwright screenshot of #/card → cards/out/ (gitignored)
.github/workflows/   refresh-data.yml (monthly data), deploy.yml (Pages + daily card), live.yml (15-min live feed)
tests/               pytest; fixtures/timetables = real API responses (2026-09-09 20:36 Berlin), gzipped
reports/             phase reports, backtest results
data/                gitignored: raw downloads + slim cache
```

## Commands
```bash
uv sync                                         # install deps
uv run python pipeline/download.py --months 3   # latest 3 monthly files → data/monthly_processed_data/
uv run python pipeline/explore.py               # schema + stations + corridor → report & stations.yaml
uv run python pipeline/slim.py                  # target-station slim cache → data/slim/
uv run python pipeline/backtest.py              # tune + holdout backtest → reports/backtest.md, config/model.yaml
uv run python pipeline/build_stats.py           # final probability tables → data/stats/*.parquet
uv run python pipeline/export.py                # static JSON → site/public/data/ (committed)
cd site && npm install && npm run dev           # local site (npm run build → site/dist/)
uv run python pipeline/conditional.py           # departure-delay conditional backtest report
uv run python pipeline/live.py --out live/live.json   # live snapshot (skips without API key)
uv run python pipeline/live.py --fixtures tests/fixtures/timetables --now 2026-09-09T20:36 --out /tmp/live.json
uv run pytest -q tests
uv run --group cards python cards/make_card.py [--date YYYY-MM-DD]   # 1080×1350 share card → cards/out/
#   needs site/dist; set CHROMIUM_PATH=/opt/pw-browsers/chromium in the cloud container
```

## Automation (.github/workflows)
- `refresh-data.yml` — monthly (3rd, after upstream's release on the 2nd) + manual (`rebuild` input):
  download months missing from the cached `data/slim` → slim → `backtest.py --strict` (fails if a delay
  forecast stops beating the line-average baseline) → build_stats → export → commit JSON to main → deploy.
- `deploy.yml` — on push to main, daily 03:47 UTC, manual, or called by the refresh: build site, render
  today's card to `site/dist/cards/{YYYY-MM-DD,latest}.png`, deploy to GitHub Pages. PRs build + render only.
- Backtest folds roll with the data (holdout = latest 4 months, tune = 4 before).
- `live.yml` — every 15 min 03–21 UTC: live.py → force-push `live.json` to orphan branch `live-data`.
  Skips (green) until repo secrets DB_CLIENT_ID / DB_API_KEY exist.
- Repo settings needed: Pages source = "GitHub Actions"; default branch = main (schedules run there only).

## Live data (Phase 5)
- API: `timetables/v1/plan/{eva}/{yymmdd}/{HH}` + `timetables/v1/fchg/{eva}`, headers DB-Client-Id / DB-Api-Key.
  XML times are Berlin local; `cs="c"` = canceled; no change entry = on time.
- Corridor runs in live data use the same ride_key rule as history (id minus trailing stop number).
- The API key never reaches the browser: the site only reads the published live.json, and ignores it when
  older than `max_age_min` or when `source != "api"` (fixture replays never show up on the real site).

## Environment notes
- Data source: `huggingface.co` (dataset `piebro/deutsche-bahn-data`). Downloads may also redirect to
  HF CDN hosts (`*.hf.co`, `cdn-lfs*.huggingface.co`, `*.xethub.hf.co`). The cloud environment's
  network policy must allow these.
- Timestamps in the data are Europe/Berlin local time; do not convert.
